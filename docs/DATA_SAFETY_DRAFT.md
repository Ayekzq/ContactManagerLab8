# Подготовка формы Google Play Data safety

## Анализ текущей реализации
Проверка исходного кода `MainActivity.kt`, `AndroidManifest.xml` и зависимостей Gradle:

- имя, телефон и электронная почта контакта сохраняются локально в `SharedPreferences` (JSON);
- приложение не обращается к системной адресной книге через разрешения;
- в `AndroidManifest.xml` не объявлены разрешения `uses-permission`;
- сторонние SDK аналитики, рекламы и Crashlytics в текущей конфигурации отсутствуют;
- приложение не отправляет контактные записи на сервер разработчика;
- учётные записи пользователей не создаются.

## Черновик ответов Data safety
1. Собирает ли приложение данные пользователя в смысле Google Play (передаёт данные с устройства приложением или его SDK)? **Нет**, пока подтверждается, что финальный APK/AAB не содержит дополнительных SDK или сетевой передачи данных. Обработка данных только на устройстве не считается сбором по определению Google Play.
2. Передаёт ли приложение данные третьим сторонам? **Нет**, по текущему исходному коду.
3. Какие категории следует указать как собираемые? **Никакие**, если финальная сборка сохраняет данные только локально и не передаёт их с устройства.
4. Шифруются ли данные при передаче? **Не применимо**, поскольку приложение не передаёт пользовательские данные по сети. Не отмечать шифрование при передаче как характеристику фактически используемого сетевого обмена.
5. Есть ли создание аккаунта? **Нет**.
6. Может ли пользователь удалить данные? **Да**: удалять отдельные записи в приложении; очистка данных приложения в системных настройках или удаление приложения удаляет локальное хранилище.

## Важная оговорка о резервном копировании Android
В `AndroidManifest.xml` сейчас установлено `android:allowBackup="true"`. Поскольку контакты хранятся в SharedPreferences, Android Auto Backup по умолчанию может включать это хранилище в резервную копию пользователя в Google Drive, если системное резервное копирование включено. Это системная функция Android; она не является отправкой данных на сервер разработчика. Этот сценарий обязательно раскрыт в политике конфиденциальности. Если поведение резервного копирования будет изменено в манифесте, нужно заново проверить декларацию и текст политики.

**Перед отправкой формы:** повторно проверить финальный AAB/APK, все SDK и сетевые вызовы. Если в последующих заданиях появятся Firebase, аналитика, Crashlytics, авторизация, синхронизация или реклама, Data safety нужно обновить.
